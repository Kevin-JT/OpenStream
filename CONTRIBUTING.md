# Contributing

## Development Workflow
1. Fork the repository
2. Create a feature branch: `git checkout -b feature/description`
3. Make changes following PROJECT_RULES.md
4. Run: `flutter analyze`, `flutter test`, `flutter build apk --debug`
5. Commit using conventional commits
6. Submit PR for review

## Code Style
- Follow existing Dart/Flutter conventions
- Run flutter format before commit
- Maintain consistent styling

## PR Process
- Describe changes clearly
- Link related issues
- Ensure all tests pass
- Address review feedback

## Reporting Issues
- Use existing issue tracker
- Include flutter version and environment details
